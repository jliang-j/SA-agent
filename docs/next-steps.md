# 后续开发路线

更新时间：2026-10-23。以本地代码和实际验收结果为准。

## 目标

产品名为“AI行业研究助手”，仓库名保留SA-agent。完成一个可演示、可测试、用户能够解释的本地研究Agent原型。
首批资料聚焦企业AI应用落地与治理，选材方法见`docs/data-guide.md`。
第一版功能基本完成，README已整理；用户已完成真实资料手动检查，并反馈数量限制后结论更集中。
已限制每个子任务最多8条事实、整份简报最多8条结论。单次耗时改善不作为稳定性能指标。
当前优先简历投递、代码理解和面试准备，不继续扩展框架或非必要功能。

## 1. DOCX接入（已完成代码与自动测试）

- 已完成：`python-docx`依赖、正文及普通表格顺序解析、切分和来源测试；上传白名单、前端选择及提示、实际本地入库、失败与重试测试。
- 边界：支持`.docx`，不支持`.doc`；不生成Word页码；不保证复杂合并/嵌套表格、文本框、修订、页眉页脚和图片内容完整提取。
- 不再扩展接入机制；尚未覆盖的格式或边界场景按需要补充检查。

## 2. 文档接入手动验收

- 用户上传一份真实DOCX及一份文本PDF，各提出一个有明确原文依据的问题。
- 检查文件状态、实际片段数、回答引用；PDF检查页码，DOCX检查片段及原文。
- 验证重名不覆盖和无效文件错误提示。
- 有阻塞问题先修复，不扩大格式范围。

## 3. 真实资料与最小评测集

- 可先用现有两份真实资料整理6～10个固定问题，不要求先扩充文档，不阻塞投递。
- 保存来源与日期，记录关键依据和预期行为。
- 覆盖单来源、多来源、资料不足、相近但不相关、时间差异或冲突。
- 将检索命中、引用匹配与人工语义复核分开记录，不能把来源通过率当作答案正确率。
- 扩充资料后重新选择资料不足负例。

## 4. 求职交付

- README已整理：项目定位、架构、环境、启动、导入、研究、测试、限制。
- 演示：正常任务、证据查看、资料不足或补查分支，准备可重复步骤。
- 简历及面试讲解：框架Agent、研究工具、DAG、RAG与核验边界，均据实际实现陈述。
- 在增加非必要功能之前先完成可投递版本。

## 5. 可选迭代（不阻塞投递）

- 导出研究简报。
- 文档来源日期、版本与冲突处理。
- 阶段耗时与调用记录；依据测量结果再优化。
- 按真实需求考虑更新、删除和更完善的失败恢复。

暂不建设多Agent系统、通用调度平台、复杂权限或更多文档格式。
